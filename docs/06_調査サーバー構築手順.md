# 調査サーバー構築手順

ADRマトリクスの「この期間を調査」ボタンから、Google Hotels の実勢価格を
その場で取りに行くための中継サーバー（`api/survey.py`）の設置手順。

**現状: コードは設置済み・テスト済み。APIキーとトークンを登録すれば動き出します。**

---

## 1. なぜサーバーが要るのか

HTMLから直接 SerpApi を叩くことはできません。

| 理由 | 内容 |
|---|---|
| **キーが晒される** | ページにキーを埋めると、開いた全員が読めます。従量課金なので漏洩＝請求 |
| **技術的に不可能** | Google／OTA はブラウザからの直接取得を CORS と対ボット防御で遮断します |
| **コストが跳ねる** | 1ページ開くたびに取得すると、5人×3回＝日次バッチの15倍の請求になります |

そこで、キーを持つ側をサーバーに置きます。

```
ブラウザ「調査」──POST──▶ api/survey.py ──▶ SerpApi ──▶ Google Hotels
   （キーを持たない）      （キーを持つ）
        ◀──── NAR正規化済みの価格 ────
```

---

## 2. 課金される経路なので、認証と上限は前提条件

このURLを知っていれば誰でも押せてしまい、押すたびに課金されます。
**「あとで付ける」ではなく、動作の前提として組み込んであります。**

| 段 | 仕組み | 既定値 |
|---|---|---|
| ① トークン照合 | `RM_SURVEY_TOKEN` と一致しなければ実行しない | **未設定なら503で全拒否** |
| ② 期間の上限 | 1回の要求で取得できる宿泊日数 | 31日 |
| ③ 日次の上限 | 1日に発行できるリクエスト総数 | 200 |
| ④ CORS | 許可オリジン以外からは呼べない | 未設定なら同一オリジンのみ |

① が「未設定なら拒否」なのは意図的です。設定漏れで誰でも叩ける状態になるのは、
課金経路では事故そのものだからです。

> ⚠️ **③はサーバーレスでは厳密なグローバル上限になりません。**
> Vercelは実行インスタンスごとにファイルシステムが分かれるため、
> インスタンスが3つ立てば最悪3倍まで通ります。
> 最終的な歯止めは **SerpApi 契約プラン側の検索上限** です。必ず設定してください。

## 3. 手元で動作確認する（キー不要）

APIキーが無くても、ボタンからサーバーまでの経路を丸ごと検証できます。

```bash
# ① 調査サーバーを起動（フィクスチャ＝擬似データを返すモード）
cd <リポジトリ>
RM_SURVEY_SOURCE=fixture \
RM_SURVEY_TOKEN=test-token-123 \
RM_SURVEY_ALLOWED_ORIGINS=http://localhost:8899 \
  python3 api/survey.py --serve 8000

# ② 別の端末で、サーバーを向いたHTMLを生成
cd engine
python3 scripts/adr_matrix.py --from 2026-11-14 --to 2026-11-30 \
  --survey-endpoint http://127.0.0.1:8000/api/survey

# ③ ページを配信して開く
cd ../out && python3 -m http.server 8899
#   → http://localhost:8899/adr_matrix.html
#   → トークン欄に test-token-123 を入れて「この期間を調査」
```

疎通だけ見たい場合（課金しません）:

```bash
curl http://127.0.0.1:8000/api/survey
# {"ok":true,"source":"fixture","tokenConfigured":true,"serpapiKeyConfigured":false,...}
```

## 4. 本番：Vercelへ設置する

### 4-1. キーを取得する

| | 用途 | 費用の目安 |
|---|---|---|
| **SerpApi** | 競合の実勢価格（主データ源） | $75/月〜（5,000検索） |
| Google Places | 施設の発見・レビュー速度。**価格は取れません** | 従量 |

### 4-2. Vercel に環境変数を登録する

Settings → Environment Variables。

| 変数名 | 値 | 必須 |
|---|---|---|
| `SERPAPI_API_KEY` | SerpApiのキー | ● |
| `RM_SURVEY_TOKEN` | 任意の長い文字列（スタッフに配る合言葉） | ● |
| `RM_SURVEY_ALLOWED_ORIGINS` | `https://<プロジェクト名>.vercel.app` | ● |
| `RM_SURVEY_SOURCE` | `serpapi`（既定） | |
| `RM_SURVEY_MAX_DAYS` | 既定31 | |
| `RM_SURVEY_DAILY_MAX` | 既定200 | |

`RM_SURVEY_TOKEN` は次のように作れます。

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(24))"
```

### 4-3. エンドポイントを設定してHTMLを再生成する

`engine/config/sources.json`:

```json
"survey_api": {
  "endpoint": "https://<プロジェクト名>.vercel.app/api/survey"
}
```

```bash
cd engine
python3 scripts/adr_matrix.py --from 2026-11-01 --to 2026-11-30
python3 scripts/build_site.py
```

`endpoint` が空のままだと、ボタンは**無効の状態で表示され**、
何を設定すれば有効になるかが画面に出ます（黙って消えるより運用しやすいため）。

### 4-4. 確認

```
https://<プロジェクト名>.vercel.app/api/survey
→ {"ok":true,"source":"serpapi","tokenConfigured":true,"serpapiKeyConfigured":true,...}
```

> 📌 `vercel.json` の `functions.includeFiles` で `engine/kanoya_rm` と
> `engine/config` を関数に同梱しています。Vercel は `api/` を自動で
> サーバーレス関数として検出しますが、**初回デプロイ時に関数が
> 認識されているか（Deployment の Functions 欄）を必ず確認してください。**
> この環境からはデプロイして確かめられていません。

## 5. 費用

エリア一括検索なので、**施設数ではなく調査日数で課金されます。**

| 操作 | リクエスト | 費用 |
|---|---|---|
| 1日分を調査 | 1 | 約2.3円 |
| 7日分を調査 | 7 | 約16円 |
| 31日分を調査（上限） | 31 | 約70円 |
| 日次バッチ（階層化収集） | 約30/日 | 約2,100円/月 |

スタッフが1日に何度押しても無視できる水準ですが、
`RM_SURVEY_DAILY_MAX` と SerpApi 側のプラン上限で二重に蓋をしてください。

## 6. このボタンが更新するもの／しないもの

| | |
|---|---|
| ✅ 更新される | 競合各社の価格、売止、市場中央値、対市場中央値、市場逼迫度 |
| ❌ 更新されない | **エンジン推奨** |

推奨価格は予約進捗（OTB）を使います。OTBはPMS／サイトコントローラーから
取り込む自社データで、SerpApiには存在しません。したがって推奨行は
夜間バッチが算出したままです。

押した直後に推奨まで動かしたい場合は、PMS連携（`data/otb.csv` の自動更新）が前提になります。

## 7. まだ残っている前提

**競合15施設の食事条件の確定**（`config/compset_overrides.json`）。

Googleが表示するのは各施設の**最安プラン**で、多くは素泊まりや朝食のみです。
一方、鹿のやが売るのは2食付きです。この換算を人が確定しないと、
NAR正規化が体系的に狂います。

```
Google表示   月日亭 ¥78,000（素泊まり最安）
鹿のや       ¥122,000（2食付き）
→ 「うちは1.6倍高い」← 誤読
→ 2食付き換算では月日亭 ¥141,000（鹿のやより高い）
```

**間違えたままでも画面上は正常な数字に見えるため、誰も気づけません。**
ここだけは自動化してはいけない工程です。

---

## 8. トラブル時

| 画面の表示 | 原因 |
|---|---|
| 調査サーバーが未設定です | `sources.json` の `survey_api.endpoint` が空。設定して再生成 |
| アクセストークンが必要です | トークン欄が空 |
| アクセストークンが違います | `RM_SURVEY_TOKEN` と不一致 |
| トークンが設定されていません（503） | サーバー側に `RM_SURVEY_TOKEN` 未登録 |
| 一度に調査できるのは31日までです | 期間を分ける、または `RM_SURVEY_MAX_DAYS` を上げる |
| 本日の調査上限に達しました | `RM_SURVEY_DAILY_MAX` に到達 |
| 接続できませんでした | URLの誤り、サーバー停止、`RM_SURVEY_ALLOWED_ORIGINS` の設定漏れ |
| 取得に失敗しました（502） | SerpApiのキー誤り・残高切れ・障害 |

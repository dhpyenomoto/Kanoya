# 奈良春日 鹿のや — レベニューマネジメント基盤

全5室オーベルジュ「奈良春日 鹿のや」を対象とした、**レベニューマネージャーの経験・力量に依存しない**ダイナミックプライシング基盤の企画書と参照実装。

近隣競合のOTA掲出情報を自動収集・正規化し、需要シグナルと組み合わせて日次の最適ADRを算出、ガードレール内は自動でOTAへ配信、逸脱分のみ人が承認する——という運用を設計しています。

> ### ⚠️ 公開範囲について
> 本リポジトリは**社内資料**です。競合施設の実名、価格ポジション、収益前提、
> 原価にかかわるガードレール値を含みます。
> **リポジトリを Private に設定し、閲覧者を Collaborator で限定してください。**
> 設定: `Settings → General → Danger Zone → Change repository visibility → Private`
> 閲覧者追加: `Settings → Collaborators → Add people`

## 中核となる考え方

| 原則 | 実装 |
|---|---|
| **判断のコード化** | 値付けを「基準価格 × 5つの補正係数」の決定論モデルとして外部化 |
| **説明可能性の強制** | 全推奨価格を「基準価格＋各要因の円建て寄与」に分解して出力 |
| **例外管理への転換** | ガードレール内は自動配信、逸脱分のみ承認キューへ（日次運用15分） |
| **記入漏れの構造的排除** | イベント表への人手入力に頼らず、競合の売止・価格急騰から需要を逆算検知 |
| **属人判断の自動校正** | 最も属人的な「基準価格をいくらに置くか」を市場整合×予算整合の2条件から機械的に解く |

## 参照実装

企画書の数式・ガードレール・出力フォーマットは、すべて動作するコードとして `engine/` に実装されています（標準ライブラリのみ、依存パッケージなし）。

### 調査条件の入力

「**いつ時点で**（本日）」「**どの宿泊日を**（対象期間）」調べるかは、
`engine/config/survey_request.json` の1か所で指定します。CLI引数でも上書きできます。

```bash
python3 scripts/survey_report.py --from 2026-11-01 --to 2026-11-30
python3 scripts/survey_report.py --from 2026-11         # 11月まるごと
python3 scripts/survey_report.py --from +30d --days 14  # 30日後から2週間
```

`as_of`（基準日）と `target`（対象期間）は独立した別概念です。
詳細は [収集パイプライン運用手順 §1.5](docs/05_収集パイプライン運用手順.md)。

### 収集パイプライン（発見 → 収集 → ADR判断）

```bash
cd engine
./scripts/run_pipeline.sh                               # APIキー不要のオフライン実行
FROM=2026-11-01 TO=2026-11-30 ./scripts/run_pipeline.sh  # 期間を絞る
```

| 工程 | スクリプト | 内容 |
|---|---|---|
| ① 発見 | `discover_compset.py` | Places API で**半径5km**内の宿泊施設を全列挙し、5軸類似度スコアでティア分類 |
| ② 確定 | `config/compset_overrides.json` | **人手**で客室数・課金方式・食事条件・uplift を確定（APIからは取得不可） |
| ③ 収集 | `collect_rates.py` | Google Hotels から階層化スケジュールで実勢価格を収集 |
| ④ 判断 | `survey_report.py` | NAR正規化して市場ポジションを算出、3シグナル合議でADR判断 |
| ⑤ 可視化 | `adr_matrix.py` | 施設×日付のADRマトリクス（端末／CSV／HTMLヒートマップ） |

実データで動かす場合は環境変数にAPIキーを設定します（コードには書きません）。

```bash
export GOOGLE_PLACES_API_KEY='...'
export SERPAPI_API_KEY='...'
SOURCE=serpapi ./scripts/run_pipeline.sh
```

## 注意事項

- 同梱のサンプルデータは**決定論的な擬似データ**であり、実データではありません。
- 施設の実績数値は非公開のため、企画書中の経営数値は公開情報と同規模施設の一般的水準から置いた**仮定値**です（「※仮定」と明記）。Phase 0 で実データに差し替える前提です。
- 競合施設名・属性も公開情報ベースの想定であり、Phase 0 で確定します。
- 競合レートの取得は、商用レートショッパーおよび公式／準公式APIに限定する設計です（OTAサイトの自前スクレイピングは規約・法務リスクから採用しません）。詳細は [データ収集設計 §3.2](docs/02_データ収集設計.md)。
- 社外へ資料を共有する必要が生じた場合は、`adr_matrix.py --anonymize` で競合名を「競合A/B/…」に伏せた版を生成できます。
